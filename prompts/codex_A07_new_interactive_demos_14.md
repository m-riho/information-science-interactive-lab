# 3. デモ①：関数の極値と勾配降下法

## 3.1 目的

関数の極値を求めるという数学的な問題を通して、勾配降下法の考え方を理解させる。

最終的には、ニューラルネットワークの重み更新との対応関係を説明する。

## 3.2 使用する関数

次の4次関数を使用する。

\[
f(x)=x^4-4x^2+x+5
\]

導関数は、

\[
f'(x)=4x^3-8x+1
\]

である。

この関数には複数の極値が存在する。

勾配降下法によって局所的な極小値を探索する様子を可視化する。

なお、極値を求める数学的な方法と、勾配降下法による数値的な探索の違いも説明する。

## 3.3 表示内容

画面には次の内容を表示する。

### 関数のグラフ

- 横軸：x
- 縦軸：f(x)
- 関数の曲線
- 現在の探索位置
- 探索位置の移動履歴
- 極小点・極大点の位置

現在の探索位置は、大きめのマーカーで表示する。

探索履歴は線または小さなマーカーで表示する。

### 計算内容

現在の状態として、以下を表示する。

- 現在のx
- 現在のf(x)
- 現在のf'(x)
- 学習率
- 更新回数

更新式も表示する。

\[
x_{n+1}=x_n-\eta f'(x_n)
\]

実際の数値を代入した計算過程を表示すること。

例：

\[
x_{n+1}=1.0-0.1\times(-3.0)=1.3
\]

※この数値は表示形式の例であり、実際には現在の関数と探索位置から計算した正しい値を表示すること。

## 3.4 操作機能

以下の操作を実装する。

1. 初期値の変更
2. 学習率の変更
3. 1ステップ実行
4. 自動実行
5. 一時停止
6. リセット

初期値はスライダーまたは数値入力で変更できるようにする。

グラフをクリックして初期位置を指定できると望ましい。

学習率は、例えば次の値を選択できるようにする。

- 0.001
- 0.01
- 0.05
- 0.1
- 0.5

学習率が大きすぎる場合には、探索が振動したり発散したりすることがある。

その様子も観察できるようにする。

ただし、数値が発散した場合には自動実行を停止し、説明メッセージを表示する。

## 3.5 数学的な説明

以下の内容を簡潔に表示する。

### 微分係数の意味

- 微分係数が正：右に進むと関数の値が増える
- 微分係数が負：右に進むと関数の値が減る
- 微分係数が0：極値の候補となる

ただし、微分係数が0であっても、必ず極小値になるわけではないことを明記する。

### 勾配降下法

勾配降下法は、微分係数の符号と大きさを利用して、関数の値を小さくする方向に変数を更新する方法である。

### ニューラルネットワークとの関係

ニューラルネットワークでは、変数xの代わりに重みwを更新する。

\[
w_{n+1}=w_n-\eta\frac{\partial L}{\partial w}
\]

ここで、

- w：重み
- L：損失関数
- η：学習率

である。

この式が、後続のデモ②と③につながることを説明する。

# 4. デモ②：JavaScriptによるニューラルネットワーク

## 4.1 目的

機械学習ライブラリを利用せず、JavaScriptだけでニューラルネットワークの学習処理を実装する。

TensorFlow.jsの内部で行われている計算の基本的な仕組みを理解させる。

## 4.2 ネットワーク構造

デモ③と比較できるように、手書き数字の「1」と「それ以外」を分類する。

入力にはMNIST形式の28×28ピクセル画像を利用する。

ネットワーク構造は次のとおりとする。

- 入力層：784ユニット
- 隠れ層：32ユニット
- 出力層：1ユニット

隠れ層にはReLU、出力層にはSigmoidを使用する。

損失関数にはBinary Cross-Entropyを使用する。

## 4.3 実装条件

ニューラルネットワークの学習処理は、外部の機械学習ライブラリを使用せず、JavaScriptで実装すること。

以下の処理を明示的に実装する。

1. 重みの初期化
2. 順伝播
3. 損失の計算
4. 誤差逆伝播
5. 重みの更新
6. 学習結果の評価

重みとバイアスは適切な方法で初期化すること。

学習率は変更可能とする。

学習アルゴリズムは、基本的なミニバッチSGDを使用する。

実行速度を考慮し、TypedArrayなどを利用してもよい。

ただし、コードの可読性を重視し、過度な最適化は避ける。

## 4.4 データセット

MNISTの手書き数字画像を利用する。

数字が1の場合は正解ラベルを1、それ以外の場合は0とする。

授業中に短時間で実行できるよう、学習データ数を制限できるようにする。

推奨設定：

- 学習データ：2,000枚
- テストデータ：500枚
- Epoch：3
- Batch size：32

データ数やEpochは操作画面から変更できるようにする。

学習データはクラスの偏りに注意して抽出すること。

特に、数字1とそれ以外の枚数が極端に偏った場合、単純な正解率だけでは分類性能を適切に評価できない。

このため、正解率に加え、数字1に対するRecallなども表示する。

## 4.5 表示内容

以下の情報を表示する。

### ニューラルネットワークの構造

784→32→1の構造を模式的に表示する。

入力層の784個のノードをすべて描画する必要はない。

省略記号などを利用して表現する。

### 学習状況

- 現在のEpoch
- 損失関数の値
- 学習データの正解率
- テストデータの正解率

損失と正解率の推移をグラフで表示する。

### 重み更新の可視化

特定の重みを1つ選択し、その値の変化を表示する。

例えば、

\[
w_{n+1}=w_n-\eta\frac{\partial L}{\partial w}
\]

の各項について、実際の計算値を表示する。

これにより、デモ①の勾配降下法と対応づける。

更新の観察は、選択した重みについて行えばよい。

## 4.6 手書き入力

HTML Canvasを利用して数字を描けるようにする。

- マウス入力
- タッチ入力
- クリア
- 判定実行

を実装する。

入力画像は28×28ピクセルに変換する。

MNISTとの形式の違いによって認識率が低下しないよう、以下の前処理を検討する。

- グレースケール化
- 白黒の方向の統一
- 余白の除去
- アスペクト比を維持した縮小
- 中央への配置
- 必要に応じた重心位置合わせ

前処理後の28×28画像も画面に表示する。

判定結果として、次の情報を表示する。

- 1であると推定した確率
- 1か、それ以外かの判定結果

確率の表示はモデルの出力値であり、必ずしも校正された確率ではないことに留意する。

# 5. デモ③：TensorFlow.jsによるニューラルネットワーク

## 5.1 目的

デモ②と同じ問題をTensorFlow.jsで実装する。

同じニューラルネットワークを、機械学習ライブラリを利用することで簡潔に記述できることを示す。

## 5.2 使用ライブラリ

TensorFlow.jsを利用する。

公式サイト：

https://www.tensorflow.org/js

ライブラリの読み込み方法は、既存プロジェクトの構成に合わせて選択する。

GitHub Pages上で動作することを必須とする。

## 5.3 モデル

デモ②と同じ構造を基本とする。

```javascript
const model = tf.sequential();

model.add(tf.layers.dense({
  inputShape: [784],
  units: 32,
  activation: "relu"
}));

model.add(tf.layers.dense({
  units: 1,
  activation: "sigmoid"
}));

model.compile({
  optimizer: tf.train.sgd(0.01),
  loss: "binaryCrossentropy",
  metrics: ["accuracy"]
});
```

比較の公平性を重視し、デモ②と③では可能な限り同じ条件を使用する。

- 同じデータセット

ただし、比較条件を画面上に表示すること。

# 6. 3つのデモの連携

今回の3つのデモは、独立した教材であると同時に、連続した学習内容として構成する。

## デモ①からデモ②

デモ①では、1つの変数xを更新する。

デモ②では、多数の重みを更新する。

両者は、損失を小さくするために微分を利用するという点で共通している。

## デモ②からデモ③

デモ②では、順伝播・誤差逆伝播・重み更新を明示的に実装する。

デモ③では、同じ処理をTensorFlow.jsによって実行する。

この違いを説明する。

## 共通の説明

3つのデモの最後に、以下の対応関係を表示する。

| 数学的な最適化 | ニューラルネットワーク |
|---|---|
| 変数x | 重みw |
| 関数f(x) | 損失関数L |
| 導関数f'(x) | 偏微分∂L/∂w |
| xの更新 | 重みの更新 |
| 極小値の探索 | 損失の小さい重みの探索 |

ニューラルネットワークでは多数の重みを同時に更新するため、実際には多変数関数の最適化問題となることも説明する。
