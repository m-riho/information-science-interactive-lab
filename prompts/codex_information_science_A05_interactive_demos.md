# Codex開発指示書：情報科学A 第5回 インタラクティブデモ

立教大学
全学共通科目「情報科学A」第5回「プログラミング言語と計算の限界」の内容を、文系学生・高校「情報」未履修者もブラウザ上で操作しながら理解できる教材として実装する。

PHP/Web → 計算可能性 → 計算複雑さ →
P=NP?」。完全な処理系や証明器ではなく、授業スライドに即した教育用シミュレーションとする。

## 5. Demo 1：3つのパラダイム

学習目標は命令型・関数型・論理型の「計算の表し方」の違い。

命令型は1からNまでの合計を使う。Nは5〜20程度。
`total=0 → +1 → 1 → +2 → 3 ...`
と状態変化を1ステップずつ表示する。Pythonの短い例も表示可。

関数型は `[1,2,...,N] → sum → 結果` と表示し、Haskellの `sum [1..N]`
を例示してよい。文法学習は目的にしない。

論理型は足し算に無理に合わせず、授業と同じ `太郎 ─親→ 花子 ─親→ 次郎`
を利用する。

「実際の言語は複数の考え方を利用できる場合がある」と注記する。

## 6. Demo 2：関数パイプライン

初期値
`[1,2,3]`。処理ブロックは「各値を2倍」「各値に1を足す」「偶数だけ残す」「合計する」。

例： `[1,2,3] → 2倍 → [2,4,6] → +1 → [3,5,7] → 合計 → 15`

順序を入れ替えた結果も比較する。元の `[1,2,3]`
は別枠に残す。ドラッグを使う場合は「上へ / 下へ」ボタンも用意する。

「純粋な関数では、同じ入力なら同じ出力となり、外部の状態を書き換えない」と補足する。

## 7. Demo 3：Prolog推論

初期知識： `parent(taro, hanako).` `parent(hanako, jiro).`

規則： `grandparent(X,Z) :- parent(X,Y), parent(Y,Z).`

問い合わせ： `?- grandparent(taro, jiro).`

1ステップごとに `X=taro,Z=jiro → Y=hanako → parent(hanako,jiro) → true`
を表示し、対応する家族グラフの辺を強調する。

数個のプリセット問い合わせを用意してよい。完全なProlog処理系や自由入力パーサは不要。教育用の小さな推論エンジンとする。「どんな問いでも自動で解けるわけではない」と注記する。

## 8. Demo 4：WebリクエストとPHP

架空の「図書検索サービス」を使う。

`検索語：[情報科学] → HTTP Request → Web Server → PHP処理 → Database → 結果生成 → HTTP Response → Browser`

架空データは「情報科学入門」「コンピュータ科学概論」「情報と社会」等。

画面内で明示する。 - PHP = 言語の約束 - PHP処理系 =
PHPで書かれたプログラムを動かすソフトウェア

教育用 `処理系を停止してみる`
ボタンを設けてもよい。停止時は「検索処理を実行できない →
サービスを提供できない」と表示する。

PHP2Shell等の実攻撃は再現しない。exploit、PoC、攻撃用HTTPリクエスト、RCE、脆弱サーバ、実際の脆弱性コードは実装禁止。

## 9. Demo 5：停止性問題

Part
1では、A「3回処理→STOP」、B「条件なしで繰り返す→LOOP」、C「一見分かりにくいが有限ステップで確認できる教育用例」を用意する。

Part 2で万能判定器Hを仮定： `Program P + Input x → H → STOP / LOOP`

Part 3で反対に動くD： `H(p,p)=STOP → DはLOOP` `H(p,p)=LOOP → DはSTOP`

Part 4でD自身を入力： `H(D,D)=STOP → D(D)=LOOP → 矛盾`
`H(D,D)=LOOP → D(D)=STOP → 矛盾`

結論：「すべてのプログラムと入力について必ず正しく停止判定するHは存在しない。」

「次へ」「前へ」「1ステップ」「最初から」を用意する。「長時間止まらない＝永遠に停止しない」ではないことも表示する。形式証明器ではなく授業の自己参照の議論の視覚化とする。

## 10. Demo 6：巡回セールスマン問題

5都市程度を2D配置し、学生が都市を順番にクリックして巡回路を作る。全都市を一度ずつ訪れ出発点へ戻る。距離をリアルタイム表示し、`最短ルートを見る`
で固定データに基づく最短例を表示する。

都市数nに対して、出発点固定・逆回りを同一・全都市間移動可能・n\>=3
の条件で候補数 `(n-1)!/2` を表示する。

例： - 5都市 → 12 - 10都市 → 181,440 - 15都市 → 43,589,145,600

仮想探索速度を選び推定全探索時間を表示してもよい。巨大値は安全な科学表記等を使いNaN/Infinityを出さない。

8都市程度以下のみ実全探索を許可し、大きい都市数では順列を生成せず式による可視化に切り替える。

必ず「総当たりが大変でも、速い解法が存在しないと証明したことにはならない」と表示する。

## 11. Demo 7：PとNP

Demo 6と同じTSPデータを再利用する。

左：「距離D以下の巡回路はある？」を探す。 右：候補巡回路を提示し、 1.
全都市を1回ずつ訪れる 2. 出発点へ戻る 3. 距離を計算 4. 距離 \<= D
を順に確認してYES/NOを表示する。

最後に、 - P：多項式時間で判定できる -
NP：YESの証拠を多項式時間で確認できる - P ⊆ NP
を表示し、「証拠を効率よく確認できるなら、その問題自体も効率よく判定できるのか？
→ P=NP? → 未解決」と進める。

「NP＝解けない問題」と表現しない。TSPの最適化問題から「距離D以下の巡回路があるか」という判定問題へ変えたことを明示する。
